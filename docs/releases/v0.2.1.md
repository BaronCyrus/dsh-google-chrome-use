# v0.2.1：改由 GitHub Actions 发布

这一版的插件代码和 0.2.0 相同，变化的是发布方式和文档。

- **来源可查**：从这一版起，npm 上的包由这个仓库的 GitHub Actions 打包发布，npm 页面上能看到它来自哪个提交。
- **发布前要过全部测试**：推 tag 后要先通过 macOS 和 Windows 上的全部 CI，才会发到 npm。
- **修正从 `link:` 切换到 npm 的步骤**：README 补上了卸载后删除符号链接这一步。少了这一步，重装时 pnpm 会把本地仓库的 `node_modules` 搬进插件目录，插件也启用失败。

验证：发布工作流的手动模式跑通了打包和 macOS、Windows 上的全部 CI，npm 也接受了这个工作流。真正发布到 npm 和生成来源证明，这一版是第一次运行。从 0.2.0 在设置页更新到这一版，发布前没法实际操作。桌面版窗口里的设置页，Windows 实机的桌面版，以及连接正在使用的 Chrome 时的勾选和允许弹窗，都还没有试过。

已经装了 0.2.0 的话，打开「设置 → Chrome Use」点「更新插件」，再完全退出并重新打开 DSH。0.1.0 没有这一页，请在 DSH 插件页卸载，再添加 `dsh-google-chrome-use@0.2.1`。
